RUN 422 — CONFIGURATION / ACTIVATION MATRIX

*** CONTAINMENT CORRECTION NOTE ***
The genesis-authority route is DISABLED. A single early startup guard in `main`
(immediately before `match config.network_mode`, after Run 102 boot verification,
before P2P service construction and any consensus task) refuses
--consensus-authority-from-genesis with EXIT!=0 for EVERY network mode and
environment. There is therefore NO flag-ON row that reaches ACTIVE — the prior
"on / present / present / YES -> ACTIVE" outcome is REMOVED. The downstream
per-mode validation rows (membership count, boot-identity equality, expected-hash)
are now unreachable in production; they survive only as retained provider-loader
tests. The legacy --validator-consensus-key CLI route is UNCHANGED and still
reachable (it is NOT the genesis route and can still build a context).

Flag: --consensus-authority-from-genesis (default: OFF)
Local signer: --signer-keystore-path (existing)
External genesis: --genesis-path (existing, boot-verified by Run 102)

Legend:
  NONE    = verification_ctx == None + ConsensusVerificationPolicy::Required
            (Run 421 unavailable-authority fail-closed default)
  EXIT!=0 = std::process::exit(1) before P2P/consensus service start
  ACTIVE  = (genesis route) NOT REACHABLE — disabled pending D4-D7
