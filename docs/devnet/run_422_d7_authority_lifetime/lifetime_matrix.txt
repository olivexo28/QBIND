RUN 422 D7 — LIFETIME / FRESHNESS REJECTION MATRIX
============================================================================
Maps `GenesisConsensusAuthority::authorize_configuration` behavior to the
task section 12.E ("Lifetime and robustness") requirements and to the tests
in crates/qbind-node/tests/run_422_d7_authority_lifetime_tests.rs.

All observed configurations are compared against an immutable authority
built from a boot-verified genesis. "Ok" means the exact founding
configuration at epoch 0; every other row fails closed.

----------------------------------------------------------------------------
C. EXPLICIT NON-CLAIMS
----------------------------------------------------------------------------
* No key rotation, revocation, or membership transition is implemented; a
  changed validator set / epoch is REFUSED, not migrated.
* This guard is code + test; it is not wired to any production activation
  (production authority stays unavailable; genesis-authority route refused).
* No protection is claimed against double-signing across clones/restarts
  beyond the per-startup identity re-validation and this configuration
  guard; no consensus-safety, QC, or equivocation claim is made here.
* The observed epoch is caller-supplied from a validated source; D7 invents
  no synthetic epoch and does not touch trust-bundle CurrentEpochUnavailable.
