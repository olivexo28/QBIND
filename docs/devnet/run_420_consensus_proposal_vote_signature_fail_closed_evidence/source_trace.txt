1. EXACT FORMER `None` BYPASS (removed)
---------------------------------------
Before Run 420, inbound Proposal and Vote verification ran only when a context
was present; a `None` context silently fell through to delivery/engine/
aggregation. Verbatim (from commit 1c22f7d):

    // inbound Proposal
    if let Some(ctx) = verification_ctx {
        let t_start = std::time::Instant::now();
        let res = verify_proposal_msg(
            &proposal, from,
            ctx.validators.as_ref(),
            ctx.key_provider.as_ref(),
            ctx.backend_registry.as_ref(),
            ...
        );
        ...
    }
    // (falls through to delivered counters / reconfig / engine when None)

    // inbound Vote
    if let Some(ctx) = verification_ctx {
        let res = verify_vote_msg(&vote, from, ...);
        ...
    }
    // (falls through to aggregation / QC / view when None)

Outbound signing had the symmetric fail-open shape: with `ctx == None` the
sign helpers returned the message unchanged (unsigned) for broadcast.

2. NEW TYPED POLICY + DEFAULT
-----------------------------
crates/qbind-node/src/binary_consensus_loop.rs
  pub enum ConsensusVerificationPolicy { Required, LocalFixtureUnsigned }   (~739)
  impl Default -> ConsensusVerificationPolicy::Required                     (~749)
  fn requires_context(self) -> bool { matches!(self, Required) }            (~760)
  struct field: BinaryConsensusLoopIo.verification_policy                   (~899)

`Required` is the Default and the only policy any production constructor
selects. When `verification_ctx` is `Some`, the policy has NO effect —
verification/signing run identically regardless of policy.
