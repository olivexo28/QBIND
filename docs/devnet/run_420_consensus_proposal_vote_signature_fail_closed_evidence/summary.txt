Scope
-----
This run corrects the fail-open `verification_ctx == None` behavior in the
binary-path consensus loop for inbound and outbound Proposal/Vote handling and
proves the correction with production-path loop tests. It is a CODE + TEST
remediation of the *configured* verification boundary. It does NOT activate
genuine production consensus signing authority for the standalone
`qbind-node` binary; that binary still has no authoritative consensus keys and
therefore, under the now-default `Required` policy, refuses to admit or emit
Proposal/Vote traffic (liveness loss is accepted; silent unauthenticated
operation is eliminated).

What changed (positive)
-----------------------
* Introduced an explicit typed policy `ConsensusVerificationPolicy`
  { `Required` (Default), `LocalFixtureUnsigned` (test-only) } — NOT another
  optional boolean.
* Under `Required` + `verification_ctx == None`, inbound Proposal and Vote are
  rejected BEFORE delivered counters, restore/deferral, reconfiguration
  observation, engine ingestion, vote aggregation, QC formation,
  view/lock/high-QC/commit mutation, and any outbound action.
* Under `Required` + `verification_ctx == None` (or context present but
  `signer == None`), outbound Proposal/Vote broadcast AND local self-injection
  are suppressed. No dummy/unsigned fallback exists.
* Added distinct, bounded, attacker-label-free context-unavailable counters for
  inbound/outbound × proposal/vote, kept separate from invalid-signature /
  missing-signature / unsupported-suite outcomes.
* Production `qbind-node` (`main.rs`) selects `Required`; the degenerate
  `io == None` in-process path also defaults to `Required`. The test-only
  `LocalFixtureUnsigned` policy is unreachable from any production constructor
  (source-level guard tests).

What remains unavailable (honest negative)
------------------------------------------
* The standalone release binary has no configured consensus signer/authority,
  so genuine production Proposal/Vote signing/verification is not demonstrated
  end-to-end on the release binary. RELEASE_BINARY_EVIDENCE=NOT-CAPTURED.
* RS1 stays OPEN; C4/C5 stay OPEN; M4/M6/S5/S7 stay Yellow; N1-N7 stay Red;
  TestNet/MainNet untouched; public DevNet remains NO-GO. No readiness item
  moves Green.
