## 5. Generated full-tree manifest artifact behavior

The full-tree manifest is generated by the reused Run 405 verifier into a **staging
directory outside** `docs/release/public-devnet` (in CI, under `${runner.temp}`),
re-validated against `PACKAGE_INTEGRITY_FULL_TREE_MANIFEST.schema.json`, checked for
full-tree coverage, and re-hashed. It is uploaded as the download-only artifact
`PACKAGE_INTEGRITY_FULL_TREE_MANIFEST.generated.json` and is **never** committed — the
harness asserts the artifact paths are outside the repo tree, none of the artifact
names is git-tracked, and the CI job fails if the working tree is dirty after the run.

## 7. Anchor drift classification

- **anchor files unchanged** — anchor `sha256` + `byte_size` equal the full-tree
  entry (16 this run);
- **anchor hashes refreshed** — acceptable only when the anchor doc was narrowly
  edited **and** its anchor entry was refreshed + documented in the same run (the
  three narrowly-edited anchor docs were refreshed in the committed anchor manifest,
  so at report time they match — reported as matching);
- **full-tree-only files** — expected because the anchor manifest is curated (71 this
  run, including the newly added `PACKAGE_INTEGRITY_CI_ARTIFACTS.md`);
- **missing anchor file** — a failure (none this run);
- **hash mismatch without documented refresh** — a failure (none this run).

## 25. Honest limitations

  is not a signed/timestamped attestation and not binary provenance.

  anchor docs, the report shows those entries as **matching** rather than as an
  outstanding drift; the deliberate refresh is documented here and in the archive
  README, not left implicit.

  run time; a path deliberately added to `.gitignore` is excluded from "publish-safe"
  coverage by design.
- Correctness of each group's readiness `status` still rests on the prior runs'
  recorded status, not a fresh re-proof of each item.
