## What this revision corrects (two observer API gaps + evidence tightening)

1. Ancestry access restricted. `SafetyDecisionView::for_each_ancestor` no longer
   exposes `&BlockNode` (which leaked the node's owned `justify_qc`/`own_qc`
   `QuorumCertificate` and its verified-justification `Arc`). It now hands the
   callback an opaque `SafetyAncestorView` exposing only identifiers, the parent
   relationship, and `Copy` scalar fields (`id`, `view`, `height`, `parent_id`,
   `justify_view`, `justify_block_id`, `has_verified_justification`). Bounded
   traversal and the voting rule are unchanged. A valid-use control doctest and a
   focused external-API `compile_fail` doctest (a `CertThief` that cannot clone a
   certificate out of an ancestor) are added on `SafetyDecisionObserver`.

2. Silent observation omission eliminated. Reproduced through real engine control
   flow (`max_pending_blocks == 0`): `register_block` evicts the candidate it just
   registered, the `NoLock` predicate succeeds without reading the block, and the
   observation input is therefore absent. The earlier revision silently skipped
   observation and self-voted anyway. The opt-in OBSERVED route now makes this
   explicit: when the observation input is missing it refuses to self-vote and
   returns no action, BEFORE the self-vote / `BroadcastVote`. The UNOBSERVED legacy
   route and the safety predicate are unchanged; no bootstrap authorization policy
   is introduced.

3. Evidence tightened. The observed-vs-legacy test now compares the COMPLETE
   outgoing `Vote` (every field) instead of only the action variant. The panic
   test requires the EXPECTED observer panic payload and rejects unrelated panics.
   The post-operation `Arc::strong_count` assertion is described as an endpoint
   (before/after) retention check — it does NOT detect temporary clones and does
   NOT measure heap allocation.
