CHAIN-IDENTITY REPRESENTATIONS (characterized, not assumed interchangeable)
----------------------------------------------------------------------------

  GenesisConfig.chain_id        String   (genesis file)
  runtime ChainId               u64      (qbind-types primitive)
  Proposal/Vote wire chain_id   u32      (qbind-wire consensus messages)

No validated u64->u32 mapping exists in the repository. v2 carries
expected_wire_chain_id as an EXPLICIT field from trusted config (fixtures/tests
only); it is never derived by truncation and never taken from a message. Absence
of a validated production mapping is a recorded blocker for production
construction (see compatibility_matrix.txt).

Existing v1 behavior characterized before replacement: two custom chain ids both
map to legacy "UNK" so v1 gives them the same domain prefix; the v1 signed body
still embeds the u32 wire chain_id, so a shared prefix alone is not a proof of
successful cross-chain replay. v1 nonetheless provides NO binding to the accepted
genesis identity or authority snapshot — the gap v2 closes.
