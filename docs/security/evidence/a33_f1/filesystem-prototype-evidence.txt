2. Isolation and explicit filesystem threat model

The test target imports only std. Linux-only openat/renameat/mkfifoat calls
use fixed relative fixture names and Linux flag constants. Every test creates
its own unique directory under std::env::temp_dir using exclusive create_dir,
then creates its own marker subdirectory and opens that directory descriptor.
All marker, temp, FIFO, symlink, moved-directory and target artifacts are
inside that test-created root. Drop removes ONLY that exact unique root;
cleanup errors fail the test. No operational paths, keys or node data are
opened. No workers/signers/network/database/startup path are involved.

Profile exercised: Linux 6.12.8+, x86_64 GNU/Linux; /tmp on ext4 at /dev/vdb.
Toolchain: rustc 1.99.1 (58cf8f9c3 2026-10-13);
cargo 1.99.1 (5f94df478 2026-08-27).

Device cache, virtualization, kernel/filesystem implementation and actual
flush-to-media behavior were NOT validated. This is not a durability profile.

Assumption: each fixture is single-threaded, with cooperating access and
controlled replacement at explicit boundaries (independent tests may run in
parallel). No hostile concurrent mutation inside identity-check/syscall
windows. Directory dev/inode checks detect scripted replacement before
publication/rename; held-descriptor relative operations avoid reopening the
marker directory for writes. Final observation is bounded and rechecked
before rename. These checks are NOT an atomic transaction: same-content
replacement, races after checks, lock/mount swaps, symlinked ancestors,
malicious inode reuse and hostile temp replacement are not fenced.
Descriptors/content equality do not establish continuity/currentness for all
participants. Such threats require a reviewed profile or refusal.

3. Executed publication sequence and failures

Success executes actual OS operations in order:
  openat(marker.tmp, O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC)
  bounded write_all of the complete supplied synthetic bytes
  File::sync_all on temporary file
  same-held-directory renameat(marker.tmp -> marker)
  File::sync_all on held directory
Only after all five return success is Ack returned. Ack contains the fixture
bytes, NOT a durable marker protocol, identity token or participation permit.
Stage trace records completed successful calls. Exact final readback is
checked separately. File and directory sync success is an observed API
result, not proof of process-crash or device power-loss persistence.

Harness injections:
  Before(stage): simulated failure before that stage's syscall.
  UnknownAfter(stage): syscall actually succeeded and trace advanced, but
    the harness simulates lost/uncertain completion and returns no Ack.
  PartialWrite: actual half-buffer write, followed by simulated error.
  ReplaceDirectoryBeforeRename / ReplaceFinalBeforeRename: actual controlled
    filesystem modification by harness before continuity checks.
These are not OS-returned write/sync faults. No real EIO, ENOSPC, sync-error
or interrupted kernel operation is claimed. Actual OS exclusive-create
AlreadyExists errors are checked for existing temporary artifacts; no
truncation, deletion or promotion occurs. No OS fault is invented from a
simulated failure.

Failure carries Stage, Cause (Harness, Os, Rejected) and Visibility:
  PriorRetained only for established pre-rename failure under the fixture
    threat model (no final replacement has occurred).
  NewVisible after successful rename, including before directory sync or
    unknown completion of directory sync. No Ack; NOT old-marker retention
    or acknowledged durability.
  Unknown for changed directory/final or an OS rename error whose replacement
    result was not established. No prior-retention inference from that error.
No error path issues an Ack. Errors do not erase old Ack objects; those
describe earlier observations, NOT necessarily current final bytes.
Repeated success/failure controls check this distinction. Leftover temp files
block subsequent exclusive-create publication; they are never auto-promoted.

inspect uses held-directory openat with O_NOFOLLOW|O_NONBLOCK, validates the
opened object is regular, and reads at most LIMIT+1 detection bytes.
It distinguishes Missing, Malformed, Oversized, Refused, and synthetic Bytes.
FIFO observation returns without waiting for a writer; directories and
symlinks are refused. No persistent encoding is chosen: "fixture:" is merely
a synthetic test prefix. A readable synthetic file is never startup/clear
permission. This prototype implements no participation API.

LIMIT=65,536 bytes is a FIXTURE bound on synthetic bytes only.
65,536 succeeds and reads back exactly; 65,537 refuses before temp creation
or final replacement. This does NOT establish that an entire encoded record,
envelope, bindings, cumulative effects/conflicts and checksum fit in 64 KiB.
The full-capacity derivation remains an unresolved prerequisite.
