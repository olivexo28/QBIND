The boundary must include:

1. Typed config model for public DevNet abuse/DoS posture:
   - per-peer max messages per second;
   - per-peer burst allowance;
   - global inbound connection rate window;
   - global inbound connection burst allowance;
   - optional per-IP or per-remote-address connection rate window if source support exists;
   - fail-open vs fail-closed behavior marker, if applicable;
   - environment binding;
   - genesis hash binding, where appropriate;
   - explicit default profile.

2. Safe default profile:
   - must preserve current behavior by default unless explicitly enabled/configured;
   - default per-peer values should match the current hardcoded behavior: 1000 msg/s + 100 burst;
   - default public DevNet profile may recommend stricter values, but must not silently alter runtime defaults unless this run explicitly wires and tests that behavior.

3. Config validation:
   - reject zero or nonsensical values;
   - reject unbounded values where they would disable protections accidentally;
   - reject values above a documented maximum unless explicitly allowed;
   - reject MainNet use unless a production policy exists;
   - reject TestNet/MainNet readiness claims.

4. Connection-rate limiter boundary:
   - pure/source-test model is acceptable for Run 361;
   - records per remote peer or address;
   - supports bounded window refill / token bucket / leaky bucket semantics;
   - exposes deterministic outcomes:
     - `ConnectionAllowed`
     - `ConnectionRateLimited`
     - `ConnectionLimiterDisabled`
     - `InvalidConfig`
     - `MainNetRefused`
     - `StateUnavailable`
   - must be non-mutating outside caller-owned fixture state.

5. Integration adapter boundary:
   - if safe and narrow, provide an adapter shape showing how `p2p_tcp` would consult the config/limiter before accepting inbound connections;
   - do not change live runtime behavior unless the integration is explicitly implemented and tested without weakening defaults;

   - if adding source metrics helpers, define exact names and test that no duplicates or misleading counters are introduced;
