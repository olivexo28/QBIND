RESET_POLICY.md must cover:
1. DevNet-only safety label: experimental, resettable, no value, no MainNet readiness, no C4/C5 closure.
2. What a DevNet reset means:
   - state may be wiped;
   - genesis may remain pinned or a successor genesis may be published;
   - prior balances/state have no value and no persistence guarantee.
3. Reset triggers:
   - safety incident;
   - data corruption;
   - trust-root/key compromise;
   - protocol-breaking upgrade;
   - unrecoverable fork;
   - planned maintenance.
4. Notice policy:
   - pre-announcement when possible;
   - emergency reset without notice allowed for safety;
   - UTC timestamped reset record required after the fact.
5. Operator action:
   - stop node;
   - back up private keys only if still trusted;
   - delete/reset data dir;
   - verify genesis hash;
   - restart using published package.
6. What never changes silently:
   - no hidden genesis;
   - no silent seed promotion;
   - no implicit trust-root replacement;
   - no MainNet/TestNet reuse.
7. Reset evidence record shape:
   - reset id;
   - reason;
   - UTC timestamp;
   - old/new genesis hash if applicable;
   - operator action;
   - safety statement;
   - no-value reminder.
8. `--authority-state-reset` posture if relevant:
   - document exactly what it does and does not reset;
   - do not imply live governance/authority C4/C5 closure.
9. No legal/financial/value guarantees.
