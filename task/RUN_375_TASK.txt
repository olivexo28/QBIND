Implementation requirements:
Add a first-class CLI surface under `qbind-node`:

1. `qbind-node identity generate`
   - accepts environment;
   - accepts role: `full-node`, `seed`, `validator-candidate`;
   - accepts output directory;
   - accepts optional validator index for validator-candidate;
   - refuses MainNet/TestNet unless explicitly supported by a future custody design;
   - writes the same files and schema-compatible public JSON as Run 374;
   - writes private ML-KEM secret key with `0600`;
   - never writes root signing key to disk;
   - produces operator-readable output.

2. `qbind-node identity verify`
   - accepts `leaf.cert.bin`;
   - re-derives NodeId and fingerprints from public material only;
   - prints schema-compatible public identity JSON or verification output;
   - reads no private secret key.

3. Optional:
   - `qbind-node identity print-public <identity-dir>`;
   - `qbind-node identity seed-candidate <identity-dir>` if useful for seed-list mapping.

4. Preserve Run 374 helper behavior or convert it into a thin wrapper around the new implementation.
   - Avoid duplication if possible.
   - Keep existing Run 374 evidence reproducible if feasible.

5. No new network behavior.
